# План тестирования мобильного приложения «Мобильный хоспис»

## 1. Цель и задачи
**Цель:** Провести ручное тестирование приложения, автоматизировать проверки и составить отчёты.

**Задачи:**
1. Определить границы и функционал приложения.
2. Составить чек-лист и тест-кейсы.
3. Выполнить ручное тестирование на эмуляторе (Android API 36).
4. Написать UI-тесты (Espresso).
5. Подключить Allure и сформировать отчёт о тестировании.

## 2. Границы приложения
В рамках тестирования проверяется следующий функционал:
- **Авторизация:** вход в приложение.
- **Новости:** просмотр списка, открытие новости, создание, редактирование, удаление, фильтрация.
- **Цитаты:** просмотр списка, раскрытие цитаты.
- **Навигация:** переходы между разделами через боковое меню.
- **Выход из аккаунта.**

## 3. Типы тестирования
- **Функциональное:** проверка работы кнопок, полей, переходов.
- **UI/UX:** проверка отображения элементов и удобства навигации.
- **Негативное:** проверка поведения при неверных данных.
- **Автоматизированное (UI):** написание и прогон Espresso-тестов.

## 4. Инструменты
- **Android Studio** (эмулятор Pixel 8, API 36)
- **Espresso** (UI-тесты)
- **Allure** (отчёты)
- **Git/GitHub**

## 5. Этапы работы

### Этап 1. Ручное тестирование
- Составить чек-лист и тест-кейсы.
- Пройти тест-кейсы на эмуляторе.
- Зафиксировать результаты в `Check.xlsx` и `Cases.xlsx`.

### Этап 2. Автоматизация
- Добавить зависимости Espresso в `build.gradle`.
- Создать директорию для тестов.
- Настроить тестовый класс.
- Написать UI-тесты по ключевым сценариям.
- Добавить флаг `android.injected.androidTest.leaveApksInstalledAfterRun=true` в `gradle.properties`.

### Этап 3. Отчётность
- Подключить Allure.
- Разметить тесты.
- Выгрузить и проверить отчёт.
- Запаковать отчёт в `allure-results.zip`.

## 6. Артефакты (в корне репозитория)
- `Plan.md` — план тестирования.
- `Check.xlsx` — чек-лист.
- `Cases.xlsx` — тест-кейсы.
- `README.md` — инструкция по запуску авто-тестов.
- `allure-results.zip` — отчёт Allure.
- `Result.md` — сравнение ручного и автоматизированного тестирования.

## 7. Критерии оценки
- Проект собирается и тесты запускаются без ошибок.
- Работает на Android API 36.
- Есть UI-тесты.
- Понятные названия тестов и методов.
- Корректный code style.
